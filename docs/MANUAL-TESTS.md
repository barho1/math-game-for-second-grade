# מסמך בדיקות אנושיות — מסע המספרים

מסמך זה מרכז את כל הבדיקות שאי אפשר (או לא כדאי) לבצע אוטומטית, ושמיועדות לבדיקה ידנית בסיום הפיתוח.
הבדיקות האוטומטיות (`npm test`, ראו `tests/README.md`) מכסות את נכונות התרגילים, ההתאמה, הכלכלה והפריסה.
כאן נבדק מה שדורש בן אדם, מכשיר אמיתי או שיקול דעת: **צליל, עברית, נראות, הבנה של ילד/ה, התקנה אמיתית וזרימות מלאות**.

המסמך מתעדכן בסיום כל שלב פיתוח. נושאים שעדיין לא נבנו מסומנים בסוף המסמך.

---

## 0. איך משתמשים במסמך

**סוגי תרחישים**
- **H (Happy path)** — השימוש התקין והצפוי.
- **E (Edge)** — מקרי קצה, טעויות, מצבים חריגים ושילובים.

**סימון תוצאה**: בעמודה האחרונה מסמנים ✅ עבר, ❌ נכשל (ורושמים הערה/צילום מסך), ⏭ לא רלוונטי.
בכל כישלון רושמים: מכשיר, דפדפן, צעדים מדויקים ומה הוצג בפועל.

**מטריצת מכשירים מומלצת** (לא חייבים את כולם, אבל לפחות הראשון):

| קוד | מכשיר |
|---|---|
| D1 | אייפד (Safari), מותקן כאפליקציה ממסך הבית — **היעד הראשי** |
| D2 | אייפון (Safari) |
| D3 | טאבלט או טלפון אנדרואיד (Chrome) |
| D4 | מחשב (Chrome, ואם אפשר גם Safari או Firefox) |

**הכנת מצב לבדיקה**
- **מצב נקי**: אזור ההורים ← "איפוס כל המשחק" ← אישור.
- **קביעת רמה/שלב**: אזור ההורים ← כרטיס "רמת פתיחה" ← בחירת ספרה בשורה המתאימה. (בחירת שלב בנתיב נושא פותחת אותו מיד.)
- **שאלת הכניסה להורים**: כפל דו־ספרתי בחד־ספרתי, למשל 27 × 8 = 216. אפשר גם לכבות אותה באזור ההורים.
- **דילוג על הסיור**: בכניסה הראשונה אפשר לדלג בכל שלב. להחזרתו: אזור ההורים ← "הפעלת הסיור מחדש".
